## Finding: the matrix was covered, the engine was not

The audit found something better and worse than a coverage gap.

**Better.** All 45 Test Gate checkboxes already mapped to at least one named
`it(...)`. Nothing in the gate was uncovered. The per-category evidence class is
now recorded in the tracker's coverage map, so a later reader cannot mistake a
mocked suite for a real one.

**Worse.** Every pre-existing workflow suite stopped at one boundary:

| Suite | Where it stopped |
|---|---|
| `evaluator-*.test.ts` | the evaluator's decision, without a step ever running |
| `step-retry.test.ts` | the wrapper's claim and retry bookkeeping, with the action replaced |
| `trigger-tenant-scope.test.ts`, `execution-handoff.test.ts` | the start boundary, with the engine mocked out |

So nothing asserted that a root actually dispatches, that a fan-in waits for
both of its prerequisites, or that one step's output becomes the next step's
input. Those are exactly the properties that fail *silently*: a fan-in that
fires early reads as a success, and an output that never propagates reads as a
step that did nothing. Unit coverage of every component is not coverage of the
assembly, and the assembly is what runs.

## Defect found: the harness, not the engine

The first run of the new suite failed on every executed step staying `PENDING`,
with `cDispatch` undefined and the duplicate-advance case seeing 2 rows instead
of 3. The cause was **not** the engine.

`src/tests/workflow/helpers/prisma-double.ts` modelled the worker route's
step-run relation as `include: { run: { workflow: true } }`. The route actually
requests:

```ts
include: { run: { include: { workflow: true } } }
```

which is the shape Prisma documents. The double therefore returned a run with no
`workflow` on it, the route threw while reading `stepRun.run.workflow.definition`,
and it answered 500. A harness gap that looked exactly like a broken engine —
and would have been mis-attributed to whichever phase owned the worker route.

`attachRun` now accepts all three include shapes actually in use:

- `{ run: true }` — `wrapper.ts`
- `{ run: { workflow: true } }` — the legacy flat form
- `{ run: { include: { workflow: true } } }` — the worker route

The double also gained `workflowRun.create` and `workflow.findUnique`, with
schema-aligned run defaults (`contextVersion: 0`). `contextVersion` is
load-bearing: the compare-and-set in `execution/state.ts` reads it and writes
`{ increment: 1 }` against it, so a run row created without it would make every
merge compare `undefined` against `undefined` and the CAS would stop meaning
anything.

**No product defect was exposed by this phase, and no product source, schema,
migration or prompt file was changed.**
